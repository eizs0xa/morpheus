# Philosophy

Morpheus exists to help teams develop agentic workflows without every project reinventing the same practices from scratch.

The important principle is simple: **extract from real use, then generalize**.

A skill, module, template, or workflow should not become Morpheus Core because it sounds useful. It should become core because a real team used it, proved it, removed project-specific assumptions, and showed that another team can benefit from it.

## Working Beliefs

- Keep the workspace understandable to a newcomer.
- Keep approved skills separate from generated documentation.
- Preserve project-specific agent files; do not overwrite them.
- Prefer a small working system over a large imagined platform.
- Use incubator space for ideas that are promising but not ready.
- Make release documentation and change management first-class.
- Never ask users to paste secrets into chat.

## Growth Path

```text
local experiment -> incubator candidate -> project evidence -> agnostic review -> approved skill/module
```

Morpheus should feel like a living playbook, not a rigid framework.
